### M4.2：邮件入库自动跑 AI process（修复 5 个并发 bug）✅ 完成

**问题**：邮件入库后（无论是首次同步还是手动 `POST /api/emails/sync`），不会自动跑 `classify / summary / spam / todo_extract / entity_extract` 5 项 skill —— 用户在邮件详情里看到的是空 summary/空 category/空 todos，需要手动调 `POST /api/emails/{id}/process`。

**根因**（5 个并发相关 bug 串联）：

1. **`EntityExtractOutput` 仍是裸 list 类型**，不是 wrapper BaseModel → 真实 LLM 兜底解析后 `result.output` 是 list，下游 `.entities` AttributeError
2. **真实 LLM 兜底路径 `_parse_from_text` 只识别 `items` 字段**，对 `EntityExtractOutput` 的 `entities`/`relations` 字段无效
3. **`_coerce_output` 同样只识别 `items` 字段**，with_structured_output 兜底返回 list 时也 AttributeError
4. **`ensure_from_provider` 中 `added_ids` 收集的是 `email.id`，但 ORM 对象未 flush → id 全是 None** → fire-and-forget 调度 0 emails → 后续任何 AI process 都不跑
5. **`Entity` 唯一约束 `(user_id, name, type)` 在并发跑 entity_extract 时跨 session 互不感知 → IntegrityError** → `_run_one` 异常吞掉，后续 29 封不再执行

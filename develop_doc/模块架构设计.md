# DeepMail 模块架构设计

> 本文件记录 DeepMail 项目的模块划分、数据模型、依赖、阶段切分及关键决策。
> 适用阶段：第一周期（AI 能力优先，邮件使用 Mock 数据）。架构随开发迭代更新。

---

## 1. 项目定位

- **产品**：AI Agent 个人邮箱助手（多用户隔离 + 自带 LLM 配置）
- **第一周期范围**：完整 AI 能力（摘要 / 待办 / 实体 / 分类 / 打标 / 垃圾 / 起草 / RAG / 多 Agent / 记忆 / 画像 / 看板 / 对话接口），**邮件使用 Mock 数据**
- **第二周期范围**：真实 IMAP/SMTP 接入（仅 163）、Celery 异步任务、Web 前端（Vue 3）、文档解析（PDF/Word/Excel/PPT）
- **邮箱适配**：当前仅网易 163；其他邮箱保留扩展接口，不实现

---

## 2. 技术栈锁定

| 层 | 选型 |
|---|---|
| Agent 框架 | LangChain + LangGraph |
| LLM 适配 | litellm（多模型统一接口）|
| Web 框架 | FastAPI + Uvicorn |
| 实时接口 | SSE 流式（聊天/Agent 输出）；WebSocket 留给后期特定功能 |
| 数据库 | PostgreSQL + pgvector（异步：asyncpg）|
| ORM / 迁移 | SQLAlchemy[asyncio] + Alembic |
| RAG | llama-index + llama-index-vector-stores-postgres（**阶段 2 落地改用原生 SQL，见 § 6.1**）|
| 鉴权 | JWT（access + refresh，passlib[bcrypt]）|
| 异步任务 | **第二周期**引入 Celery + Redis |
| 邮件 IO | 第一周期 Mock Provider；第二周期 imap-tools / smtplib / mailparser |
| 文档解析 | **第二周期**：pdfplumber / PyMuPDF / python-docx / pandas / python-pptx / VLM |

## 4. 数据模型（第一周期要建的表）

```
users(id, username, password_hash, role, llm_config_json, created_at)
llm_configs(user_id, provider, base_url, api_key, chat_model, embed_model, rerank_model)

emails(id, user_id, message_id, sender, recipients, subject, body_text, body_html,
       sent_at, received_at, thread_id, labels[], categories[], is_read, spam_score,
       summary, todos_extracted, entities_extracted, raw_payload_json)

todos(id, user_id, email_id, content, due_date, status, priority, created_at)

labels(id, user_id, name, color)             -- 用户级标签
categories(id, user_id, name, rules_json, is_system)   -- 4 个系统预设不可改
persona(id, user_id, profile_json, updated_at)

knowledge_chunks(id, user_id, partition, source, content, embedding vector,
                 metadata_json, created_at)
entities(id, user_id, name, type, embedding)
relations(id, user_id, subject, predicate, object, confidence, source_email_id)

chat_sessions(id, user_id, title, created_at)
chat_messages(id, session_id, role, content, tool_calls_json, tokens_used, created_at)
memory_short_term(session_id, state_json)      -- checkpointer 落 PG
memory_medium_topics(id, user_id, topic, summary, embedding, created_at)
memory_long_term(id, user_id, key, value, importance, decay_score, updated_at)
```

**关键约定**：
- 所有表 `id` 用 UUID；带 `user_id` 字段做多用户隔离
- `embedding` 列由 pgvector 提供，维度与所选 Embedding 模型一致
- 三元组关系（entities / relations）按设计文档要求实现 ADD/UPDATE/DELETE/NOOP

## 5. AI 单点能力（阶段 1）

| 能力 | 输入 | 输出 | 备注 |
|---|---|---|---|
| 摘要 | 邮件正文 | 摘要文本 | 按 sender/receiver/date/labels 元数据先过滤 |
| 待办抽取 | 邮件正文 | Todo 列表（content, due_date）| 支持特定日期/截止/无日期 |
| 实体关系抽取 | 邮件正文 | 三元组 + 实体（向量相似度 0.85 合并）| 落 entities/relations 表 |
| 分类 | 邮件 | category_id | 默认 4 类（常规/验证码/广告/有害）|
| 打标 | 邮件 | labels[] | 自动打标后用户确认存储 |
| 垃圾过滤 | 邮件 | spam_score + is_spam | 与分类解耦，可独立开关 |
| 辅助起草 | 用户指令 + 原邮件上下文 + 人格画像 | 草稿文本 | 草稿需用户确认才发 |

## 6. RAG（阶段 2）

检索流程（沿用 `技术栈.md`）：
```
查询理解（改写/扩展）→ 并行检索（向量 + BM25）→ 结果融合（RRF）
→ 重排序（Reranker）→ Top-K 片段 → LLM 生成
```

- **chunk 策略**：按邮件 thread（会话）分块
- **vector payload**：sender / receiver / date / thread_id / labels（支持时间过滤 `date >= '...'`）
- **附件单独解析入库**（第二周期）

### 6.1 实现偏离说明（2026-08 阶段 2 落地）

架构文档 `技术栈.md` 中 RAG 框架选择 **llama-index**，但阶段 2 实际落地采用**原生 SQL 替代**，**未使用 llama-index**。原因：

| 维度 | llama-index 方案 | 原生 SQL 方案（当前实现） |
|---|---|---|
| 嵌入集成 | `langchain_embeddings` wrapper | 直接 `httpx` / `AsyncOpenAI`（gitee Qwen3 OpenAI 兼容） |
| 向量检索 | `VectorStoreIndex` + `PGVectorStore` | 手写 SQL `embedding <=> :qvec`（cosine） |
| BM25 | `BM25Retriever`（基于 `rank_bm25` 内存倒排） | PostgreSQL `to_tsvector` + `ts_rank`（原生） |
| RRF | 自实现 | 自实现 `_rrf_fuse()` |
| Chunk | `SentenceSplitter` | 手写 `chunk_text()` 800/120 滑动 |
| 异步 | 需配 `Settings.llm` 等全局 | 完全异步原生 |
| 复杂度 | 框架封装层多，调试链路长 | 简单直接，单步 SQL 可解释 |
| 复用性 | 与 SQLAlchemy 异步 session 解耦 | 复用现成 `get_db()` 依赖 |

**保留 llama-index 依赖的原因**（`pyproject.toml` 仍声明）：
1. 第二周期接附件解析（PDF/Word/Excel）时，llama-index 的 `SimpleDirectoryReader` 比手写解析器更稳
2. 跨分区联合检索、复杂 query 改写等高级特性，llama-index 现成可用
3. 减小迁移成本（不需要重新装依赖）

**迁移路径**：第二周期如确认附件解析或 query 改写要重度依赖 llama-index，再把 `app/rag/` 三个文件迁到 `llama-index` 实现。否则保持现状。

## 7. 多 Agent 编排（阶段 3，LangGraph）

**图模式**：Supervisor（中央调度）+ 专业节点（按意图分发）

**节点清单**（来自 `邮箱助手项目设计文档.md` L214–L236）：
- 意图识别 / 搜集关联邮件 / 搜集特定信息 / 起草邮件草稿
- 邮件内容确认 / 分类邮件 / 邮件摘要 / 垃圾邮件过滤
- 待办事项生成 / 邮箱整理 / 最近邮件总结 / 邮件日报

**兜底机制**（harness 工程）：
- 最大迭代步数（防死循环）
- 上下文 token 压缩（超阈值时摘要压缩）
- 工具调用失败重试 + 异常上报
- Token 用量监测（按 session / 按日 / 按月）

## 8. 记忆体系（阶段 4）

| 层 | 存储 | 生命周期 | 用途 |
|---|---|---|---|
| 工作记忆 | Python 内存 | 当前请求 | LangGraph 状态 |
| 短期/会话记忆 | PG（checkpointer）| 7–30 天 | 多轮对话恢复 |
| 中期/话题记忆 | PG + pgvector | 7–30 天 | 跨会话话题检索 |
| 长期/语义记忆 | 结构化 PG 表 + 向量 | 不限 | 用户偏好/事实 |

**自动提炼**（distiller）：`(主体, 谓词, 客体, 置信度)` → ADD/UPDATE/DELETE/NOOP
